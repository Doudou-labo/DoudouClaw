**Ce que fait un MCP LanceDB** 🧠
- Créer/lire des tables vectorielles
- Faire des recherches par similarité sémantique
- Stocker des embeddings avec métadonnées

**Le problème dans notre cas** ⚠️

Les implémentations trouvées (`lance-mcp`, `mcp-server-lancedb`, `lancedb_mcp`) nécessitent toutes :
1. **Un build manuel** (pas de `npx -y` direct)
2. **Un chemin vers leur propre index LanceDB** — pas le format utilisé par le plugin mémoire OpenClaw
3. **Pas de connexion native à** `/root/.openclaw/memory/lancedb` (le format interne OpenClaw est géré par `memory-lancedb` plugin, pas directement accessible via ces MCP)

**En résumé** 💬 : un MCP LanceDB générique ne peut **pas se brancher** sur la mémoire OpenClaw directement — c'est le plugin `memory-lancedb` natif qui fait le pont, et il expose déjà ça via `memory_recall` / `memory_store` 🔌

**Ce qu'on a = ce qui suffit** ✅ :
- `memory_recall` → recherche sémantique dans LanceDB (déjà ultra-optimisée)
- `memory_store` → écriture d'embeddings
- Pas de doublon inutile à gérer

**Ce que fait `mcporter`** 🔧
Un CLI pour interagir avec des serveurs MCP directement depuis le terminal :
```bash
mcporter list                          # liste les serveurs configurés
mcporter list datagouv --schema        # voir les tools dispo
mcporter call datagouv.search_datasets query=immobilier  # appeler un tool
mcporter auth <server>                 # gérer l'OAuth
mcporter config add/remove             # gérer la config
```

**Pourquoi c'est intéressant** ✅
- Tester un MCP rapidement en ligne de commande sans passer par le chat
- Débugger un serveur MCP qui ne répond pas
- Générer des types TypeScript depuis un serveur MCP
- Appeler des outils ad-hoc sans passer par la config OpenClaw

**Pourquoi c'est pas prioritaire pour toi** 💬
Tu as déjà tes 6 MCP configurés et tu les utilises via le chat — c'est exactement l'usage optimal. `mcporter` serait utile si tu voulais **scripter** des appels MCP dans des crons ou des scripts bash, genre :
```bash
mcporter call sqlite.query sql="SELECT * FROM followups WHERE status='A_FAIRE'"
```

**Mon verdict** ⚖️ : utile pour du debug ou du scripting avancé, mais pas indispensable maintenant. Si un MCP bug ou si tu veux tester un nouveau serveur sans toucher à la config, là ça devient pratique 🎯

Tu veux qu'on l'installe quand même ou on garde ça en réserve ?
