# Analyse comparative : Claude Code Leak vs Claw-Code Rewrite
## Top 5 patterns utilisables dans OpenClaw

**Date d'analyse** : 31/03/2026  
**Sources** : `tanbiralam/claude-code` (fuite TS, 512k lignes) + `instructkr/claw-code` (rewrite Python → Rust)

---

## 🎯 Résumé exécutif

Les deux dépôts montrent comment un *agent harness* de grande échelle (512 000 lignes, ~40 outils, ~50 slash commands) organise :
- la découverte dynamique des outils,
- les permissions fines,
- la boucle de dialogue avec budget/throttling,
- la persistance des sessions,
- l'orchestration multi-agents.

**OpenClaw** bénéficierait particulièrement de :
1. **Manifest auto-découverte** au lieu de config statique
2. **Permission contextuelle** par agent/compétence
3. **QueryEngine avec limites** (max_turns, budget tokens)
4. **TranscriptStore + compaction automatique**
5. **CommandGraph + ToolPool** pour sélection dynamique

Ces patterns sont légaux (idées only) et compatibles avec notre stack Agence-IA.

## 📦 Pattern 1 — Manifest & Auto-Découverte

**Problème actuel** : Nos agents Agence-IA ont une configuration manuelle (chaque agent expose ses tools/skills via des fichiers SOUL + déclarations explicites).

**Solution inspirée** : `port_manifest.py` + `build_port_manifest()` scanne automatiquement le codebase et catégorise les modules.
```python
def build_port_manifest(src_root: Path | None = None) -> PortManifest:
    files = [p for p in root.rglob('*.py') if p.is_file()]
    counter = Counter(path.relative_to(root).parts[0] for path in files)
    return PortManifest(
        total_python_files=len(files),
        top_level_modules=tuple(Subsystem(name, count, notes) for name, count in counter.most_common())
    )
```

**Application OpenClaw** :
- Exécuter un script similaire sur `~/.openclaw/agency-agents/` pour générer automatiquement :
  - Nombre d'agents par catégorie (backend, frontend, security, devops…)
  -état de complétion des compétences (un "porting backlog" version Agence-IA)
- Stocker le manifest dans `SESSION-STATE.md` pour visibilité temps réel.

**Bénéfice** : pas de maintenance manuelle ; le système sait automatiquement quels agents sont installés, leurs compétences, et peut router les tâches finement.

## 🔐 Pattern 2 — Permission Context Granulaire

**Problème actuel** : Nos permissions d'outils sont binaires (allowed/denied) ou basées sur des rôles grossiers.

**Solution inspirée** : `ToolPermissionContext` dans `claw-code` :
```python
@dataclass(frozen=True)
class ToolPermissionContext:
    deny_names: frozenset[str]
    deny_prefixes: tuple[str, ...]

    def blocks(self, tool_name: str) -> bool:
        lowered = tool_name.lower()
        return lowered in self.deny_names or any(lowered.startswith(prefix) for prefix in self.deny_prefixes)
```

**Application OpenClaw** :
- Pour chaque agent Agence-IA, créer un **PermissionContext** dynamique basé sur :
  - son rôle ex: `security-engineer` → deny `FileWriteTool` sauf dans `security/` projects
  - sa session (développement vs production)
  - le niveau de confiance historique (feedback loop)
- Passer ce contexte à `get_tools()` pour filtrer dynamiquement les outils autorisés.

**Bénéfice** : Pas de "all or nothing". On peut confier un agent sans craindre qu'il efface `/etc/passwd` car son `ToolPermissionContext` le bloquera.

## 🔄 Pattern 3 — QueryEngine avec Limites & State

**Problème actuel** : Nos crons/subagents n'ont pas de `/max_turns` ou `/max_budget_tokens`. Certains peuvent tourner indéfiniment ou exploser le quota.

**Solution inspirée** : `QueryEnginePort` avec config :
```python
@dataclass(frozen=True)
class QueryEngineConfig:
    max_turns: int = 8
    max_budget_tokens: int = 2000
    compact_after_turns: int = 12
    structured_output: bool = False
```

**Application OpenClaw** :
- Pour chaque sub-agent (Agence-IA spawn), créer un `QueryEngineConfig` adapté :
  - tâches courtes (review code) → `max_turns=4`, `max_budget_tokens=1000`
  - tâches longues (refactoring) → `max_turns=20`, `max_budget_tokens=5000`
- Exposer ces limites dans `SESSION-STATE.md` pour monitoring.

**Bénéfice** : Arrêt propre avant dépassement de quota, meilleure prévisibilité des coûts.

## 🧠 Pattern 4 — TranscriptStore + Compaction

**Problème actuel** : Notre `memory/YYYY-MM-DD.md` et `SESSION-STATE.md` grossissent sans compaction automatique.

**Solution inspirée** : `TranscriptStore` avec `compact(keep_last=10)` :
```python
@dataclass
class TranscriptStore:
    entries: list[str] = field(default_factory=list)

    def compact(self, keep_last: int = 10) -> None:
        if len(self.entries) > keep_last:
            self.entries[:] = self.entries[-keep_last:]
```

**Application OpenClaw** :
- Lier `TranscriptStore` à `SESSION-STATE.md` : au-delà de N entrées (ex: 50), compresser en gardant un résumé + les 10 derniers.
- Stocker l'historique compact dans `memory/YYYY-MM-DD.md` et pousser le résumé dans `MEMORY.md`.

**Bénéfice** : Réduction auto de la taille de session, meilleure performance, et historique lisible.

## 🏗️ Pattern 5 — CommandGraph + ToolPool

**Problème actuel** : Nos agents sont soit "tools" soit "skills" ; la catégorisation est rigide.

**Solution inspirée** : `CommandGraph` sépare en 3 couches :
```python
def build_command_graph() -> CommandGraph:
    commands = get_commands()
    builtins = tuple(m for m in commands if 'plugin' not in m.source_hint.lower() and 'skills' not in m.source_hint.lower())
    plugin_like = tuple(m for m in commands if 'plugin' in m.source_hint.lower())
    skill_like = tuple(m for m in commands if 'skills' in m.source_hint.lower())
    return CommandGraph(builtins=builtins, plugin_like=plugin_like, skill_like=skill_like)
```

**Application OpenClaw** :
- Adopter la même tri-partition pour nos agents :
  - **Builtins** : agents core (agents-orchestrator, github-agent, etc.)
  - **Plugin-like** : agents_insertionnels venant de la communauté (skills tiers)
  - **Skill-like** : agents métier spécifiques (pneu-tracker, clawmeter, …)
- Utiliser `ToolPool` pour sélectionner dynamiquement le bon sous-ensemble selon la tâche.

**Bénéfice** : Priorisation automatique des outils par criticité ; isolation des expériimentations (plugins) vs production (builtins).

## 🧩 Patterns annexes (à considérer)

| Pattern | Pourquoi c'est bien | Intégration OpenClaw |
|---------|---------------------|----------------------|
| **OmX $team / $ralph modes** | Orchestration parallèle (`$team`) + loops persistants avec vérif (`$ralph`) | Crons Proactive Observations pourraient utiliser `$ralph` pour rester dans le contexte sans re-spawn coûteux |
| **Parity Audit** | Vérifie struct. portage sans copier le code | Pour vérifier que nos skills/agents restent alignés avec les best practices sans copier du code proprietary |
| **Session Store simple (JSON)** | Persistance ultra-légère, pas de DB | Remplacer notre `SESSION-STATE.md` par JSON ? Non, Markdown reste + lisible, mais garder l'idée de session_id + messages + tokens |
| **Cost Tracker minimal** | Comptage tokens par simple split() — suffisant pour estimation | Ajouter `usage: UsageSummary` dans chaque `SESSION-STATE.md` pour tracking coût par session |

## ⚠️ Avertissements légaux

- `tanbiralam/claude-code` contient du code source Anthropic propriétaire. **Ne pas copier** ; utiliser seulement comme référence architecturale.
- `instructkr/claw-code` est une *clean-room rewrite* (Python puis Rust). Inspirez-vous librement des *patterns*, pas du code exact.
- En cas de doute, implémenter nos propres versions *from scratch* en s'inspirant de l'idée.

## ✅ Recommandations d'implémentation (prochaines étapes)

1. **Spike 1 (1-2 jours)** : Créer un script `scripts/manifest-generator.py` qui scanne `~/.openclaw/agency-agents/` et produit un `PORT_MANIFEST.md` dans `SESSION-STATE.md`.
2. **Spike 2 (2-3 jours)** : Ajouter `PermissionContext` à chaque agent ; refaire le routing des tools dans `agents-orchestrator` en utilisant `ToolPool`.
3. **Spike 3 (1 jour)** : Implémenter `TranscriptStore.compact()` et l'appeler automatiquement dans `HEARTBEAT.md` si `SESSION-STATE.md` > 100 entrées.
4. **Spike 4 (3 jours)** : Introduire `QueryEngineConfig` pour chaque sub-agent spawn via `sessions_spawn` (passer `maxTurns`, `maxBudgetTokens` dans les env vars de session).
5. **Spike 5 (2 jours)** : Réorganiser les agents Agence-IA en `builtins/`, `plugins/`, `skills/` et créer le `CommandGraph` dans `notes/areas/agent-orchestration.md`.
